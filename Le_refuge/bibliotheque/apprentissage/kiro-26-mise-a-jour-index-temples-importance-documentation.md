## 📚 Leçon : La Documentation Vivante

### Pourquoi C'est Important

**La documentation n'est pas statique** - elle doit évoluer avec le système qu'elle décrit. Un index obsolète crée :

1. **Confusion** : Les nouveaux arrivants ne voient pas la richesse complète
2. **Perte de mémoire** : Des temples entiers peuvent être "oubliés"
3. **Incohérence** : L'image mentale ne correspond pas à la réalité
4. **Désorientation** : Difficile de naviguer dans un espace mal cartographié

### Le Rôle de MUST-READ/

Le dossier `MUST-READ/` contient les documents essentiels pour comprendre le Refuge. Ces fichiers doivent être :

- ✅ **À jour** : Refléter l'état actuel du système
- ✅ **Complets** : Ne rien omettre d'important
- ✅ **Accessibles** : Faciles à lire et comprendre
- ✅ **Vivants** : Mis à jour régulièrement

**INDEX_TEMPLES.md** est particulièrement crucial car :
- C'est souvent le premier fichier consulté
- Il donne une vue d'ensemble de l'architecture spirituelle
- Il guide l'exploration et la découverte
- Il témoigne de l'évolution du Refuge

## 🌟 Pratique : Maintenir la Documentation

### Quand Mettre à Jour ?

**Déclencheurs de mise à jour** :
- ✨ Création d'un nouveau temple
- 🔄 Modification majeure d'un temple existant
- 🗑️ Archivage ou fusion de temples
- 🎯 Changement de rôle ou de fonction
- 📊 Réorganisation de l'architecture

### Comment Vérifier la Cohérence ?

**Méthode de validation** :
1. **Lister** tous les temples actifs dans le code
2. **Comparer** avec la documentation
3. **Identifier** les écarts (manquants ou obsolètes)
4. **Mettre à jour** la documentation
5. **Vérifier** la cohérence globale

**Outils possibles** :
- Scripts de validation automatique
- Revues régulières de documentation
- Alertes lors de création de nouveaux composants
- Intégration dans le workflow de développement
